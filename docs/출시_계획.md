## 순서

병렬로 갈 수 있는 것은 병렬로 적었다. **2번이 가장 오래 기다리므로 제일 먼저 넣는다.**

### 0. 개발 빌드 (지금 막혀 있는 것)

```
cd C:\dev\RECoco\app
eas build --profile development --platform ios
```

이게 있어야 결제·OCR·카메라·코코몬 카드 실물을 처음으로 본다.
**폰에서 확인할 목록**: 운동·음악 폼, 롤 이어붙이기, 코코몬 카드, 달력, 카메라·공유·백업,
가게 검색(키보드가 목록을 가리는지).

### 1. 이름·번들 ID 선점 확인 ← 제일 먼저, 5분

SubFlow는 **앱 이름과 번들 ID를 둘 다 뺏겨서** `MySubFlow - 구독 관리` / `app.mysubflow`로
바꿔야 했다. 레코코도 등록 전에 확인할 것:

- App Store에서 **"레코코"** 검색 → 같은 이름이 있으면 `레코코 - 기록 영수증` 같은 부제 붙은 이름으로
- App Store Connect에서 번들 ID `com.yoongyeongeun.recoco` 등록 시도 → 막히면 바꾼다
- ⚠️ 번들 ID를 바꾸면 `app.json`의 iOS `bundleIdentifier`와 안드로이드 `package`를 **같이** 바꾼다

### 2. 유료 앱 계약 (세금·은행) ← 승인 대기 2~5일, 제일 먼저 넣을 것

App Store Connect → 비즈니스 → 유료 앱 계약 동의 + **은행 계좌** + **세금 정보**(한국/미국 W-8BEN).

⚠️ **이 계약이 "활성"이 되기 전에는 앱 내 구입 상품이 "제출 준비 안 됨"에서 안 넘어간다.**
SubFlow는 무료라 이 단계가 아예 없었다 — 레코코에서 처음 겪는 대기다.

### 3. 상품 22개 등록 + 원화 최저가 확인

`marketing/App Store/iap-products.md`에 복붙용 표를 만들어 둘 것.

- 카테고리 6개 × 1,500원 / 테마 7개 × 1,000원 / 옷 9개 × 1,000원 (모두 **비소모성**)
- ⚠️ **상품 ID는 등록하면 영영 못 바꾼다**
- 각 상품에 **심사용 스크린샷 1장**과 설명이 필요하다 (22개 전부)
- 여기서 **원화 최저가를 확인** → 확정 대기 중인 조건부 결정이 풀린다:
  - 최저가가 1,500원이면 → 코코 옷 9개를 전부 기록 보상으로 풀고 테마만 판다
  - 1,000원을 팔 수 있으면 → 지금 구성 그대로

### 4. 개인정보 처리방침 올리기

`landing/` 폴더를 Cloudflare Pages 프로젝트로 배포 (SubFlow와 같은 방식).

- `https://recoco.pages.dev/privacy` — 스토어 필수
- 도메인은 안 사도 된다. `*.pages.dev`로 충분하다
- 올린 뒤 앱 **설정 화면 "정보"에 링크**를 넣는다

### 5. 스크린샷

- ⚠️ **1284×2778로 만든다.** SubFlow 때 1290×2796(아이폰 15 Pro Max 실해상도)을
  올렸다가 거부당했다
- 6.7인치 + 6.5인치 두 규격, 최대 10장
- **앱 설치 시트에는 처음 3장만 보인다** → 앞 3장에 제일 예쁜 영수증을 놓을 것
- 레코코는 영수증 자체가 그림이라 `design/tools`의 PNG 미리보기를 그대로 쓸 수 있다

### 6. 등록 정보 + App Privacy 설문

`marketing/App Store/listing-ko.md`, `app-privacy-ko.md` 참고.

⚠️ **로케일마다 따로 넣어야 한다.** 한국어에만 넣고 영어(미국)를 비워 두면 제출이 막힌다 —
설명·키워드·지원 URL·개인정보 처리방침 URL 전부.

### 7. 프로덕션 빌드 → 제출

```
npx eas-cli build -p ios --profile production --non-interactive --no-wait
npx eas-cli submit -p ios --latest --non-interactive
```

- `--auto-submit`을 붙이면 빌드 후 업로드까지 간다 (빌드 ~5분 + 업로드 대기열 ~30분)
- ⚠️ `autoIncrement`는 **원격 카운터**라 "다음 빌드 = 승인된 빌드 + 1"이 아니다.
  만들기 전에 `npx eas-cli build:list`로 확인
- 앱 내 구입은 **첫 심사 때 앱과 같이 심사된다** → 심사 메모에 상품 구조를 설명할 것

### 8. 심사

- 첫 제출에서 **Guideline 2.1(정보 요청) 반려는 흔하다.** SubFlow도 그랬다. 앱 결함이 아니라
  "정보를 더 달라"는 요청이었다
- ⚠️ 심사 메모와 회신 칸은 **각각 4,000자 제한**. 넘으면 잘리는 게 아니라 버튼이 비활성화된다
- 회신을 **먼저** 보내고 그다음에 빌드 교체 → 심사 업데이트 순서로
- 레코코에서 물어볼 만한 것: **구매 복원 버튼**(설정에 있음 ✓), 카테고리 잠금이 무엇인지,
  코코몬 카드 등급이 무작위인 점(뽑기 = 확률 공개 의무가 있는지)

### 9. 출시 후

- ⚠️ **JS만 바뀐 수정은 `eas update`(OTA)로 심사 없이** 나간다. 네이티브가 안 바뀌면
  runtimeVersion이 같아서 기존 빌드에 그대로 붙는다
- 새 빌드가 필요하면 `app.json`의 `version`을 **1.0.1**로 올린다 — 심사를 통과한 1.0.0에는
  새 빌드를 못 올린다
- 운동 건강 연동(HealthKit)은 출시 후 업데이트로 (카테고리가 이미 있어 새 상품 등록이 없다)

## 기간

| 구간 | 걸리는 시간 |
|---|---|
| 폰 검증 + 고치기 | 며칠 ~ 1주 (제일 큰 변수) |
| 유료 앱 계약 승인 | 2~5일 (대기, 다른 일과 병렬) |
| 상품 22개 등록 | 2~3시간 |
| 스크린샷·문구·설문 | 1~2일 |
| 심사 | 1~3일, 2.1 반려 시 +2~3일 |

**막힘없이 3~4주, 현실적으로 5~6주.** 가장 큰 변수는 폰 검증이다 — 운동·음악 폼, 코코몬 카드,
롤 이어붙이기는 **아직 실기기에서 한 번도 안 돌았다.**

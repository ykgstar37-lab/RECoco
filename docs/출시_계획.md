## 출시 방식: 무료로 먼저 낸다 (2026-09-28 확정)

v1.0 은 **모든 카테고리·테마·코코 옷을 연 채로 무료** 출시한다. 유료 상품 22개는 나중에
사용자가 늘면 업데이트로 붙인다.

**왜**: 유료로 팔려면 사업자등록번호가 필수인데(아래 2번), 소액 매출에서는 부가세보다
**신고 의무와 대행 비용**이 손익을 가른다. 쓰는 사람이 생긴 뒤에 등록하는 것이 맞는 순서다.
SubFlow도 무료라 이 단계가 아예 없었다.

**기존 사용자는 계속 무료로 쓴다.** 유료화 이후에 설치한 사람부터 사게 한다 —
이미 쓰던 사람에게서 빼앗는 모양이 되면 안 된다.

> ✅ **첫 실행 날짜 기록은 2026-09-28 에 넣었다** — `app/src/lib/since.ts`,
> 키 `recoco.since.v1`, 홈 화면이 뜰 때 `markFirstRun()`. 웹에서 실제 저장·재실행 시
> 덮어쓰지 않음을 확인했다. 서버가 없으므로 "언제부터 쓴 사람인지"의 근거는 이 값뿐이다.
> **키 이름을 바꾸거나 지우지 말 것.**
>
> 유료화할 때는 `startedBefore('유료화한 날')` 로 갈라서, 그 전부터 쓰던 사람에게는
> 잠긴 것 없이 그대로 열어준다.

유료화 판단 기준은 미리 정해 둔다 (예: 다운로드 500, 꾸준히 쓰는 사람 50명).
유료화할 때 **App Store Small Business Program 신청**을 잊지 말 것 — 자동이 아니고,
신청해야 수수료가 30%에서 **15%**로 내려간다.

## 순서

병렬로 갈 수 있는 것은 병렬로 적었다.
**v1.0 에서는 2번(유료 앱 계약)과 3번(상품 등록)을 건너뛴다.**

### 0. 개발 빌드 (지금 막혀 있는 것)

```
cd C:\dev\RECoco\app
eas build --profile development --platform ios
```

이게 있어야 결제·OCR·카메라·코코몬 카드 실물을 처음으로 본다.
**폰에서 확인할 목록**: 운동·음악 폼, 롤 이어붙이기, 코코몬 카드, 달력, 카메라·공유·백업,
가게 검색(키보드가 목록을 가리는지).

### 1. 이름·번들 ID 선점 확인 ← 제일 먼저, 5분

SubFlow는 **앱 이름과 번들 ID를 둘 다 뺏겨서** `MySubFlow - 구독 관리` / `app.mysubflow`로
바꿔야 했다. 레코코도 등록 전에 확인할 것:

- ✅ **2026-09-28 사용자가 App Store에서 "레코코" 검색 → 같은 이름 없음.** 이름은 `레코코` 그대로 간다
- App Store Connect에서 번들 ID `com.yoongyeongeun.recoco` 등록 시도 → 막히면 바꾼다
- ⚠️ 번들 ID를 바꾸면 `app.json`의 iOS `bundleIdentifier`와 안드로이드 `package`를 **같이** 바꾼다

### 2. 유료 앱 계약 (세금·은행) ← 제일 먼저 넣을 것

⚠️ **이 계약이 "활성"이 되기 전에는 앱 내 구입 상품이 "제출 준비 안 됨"에서 안 넘어간다.**
SubFlow는 무료라 이 단계가 아예 없었다 — 레코코에서 처음 겪는 일이다.

**계약 서명** (10분, 되돌릴 수 없음)

- **계정 소유자(Account Holder)만** 서명할 수 있다 (`yge0307@gmail.com`)
- App Store Connect → 상단 **비즈니스** → **계약** 탭 → **유료 앱** 행 →
  **약관 보기 및 동의하기** → 2단계 인증 코드 → 동의

**그다음 세 가지를 따로 채운다** (서명과 별개. 셋 다 끝나야 "활성"이 된다)

1. 담당자 정보 — 선임·재무·기술·법률·마케팅. 1인 개발자는 전부 본인
2. 은행 계좌 — 국내 은행 가능. **드롭다운 빼고 전부 영문.** 영문 예금주명이 계좌와 같아야 하고 SWIFT 코드가 필요
3. 세금 정보 — 아래

**⚠️ 한국 세금 정보 — 사업자등록번호가 사실상 필수다 (2026-09-28 확인)**

애플이 한국에 요구하는 것:

- **사업자등록번호(BRN)** + 90일 이내 발급 **영문 사업자등록증명**, 또는
- **국세청 고유번호** + 90일 이내 **고유번호증** (비영리용)

번호가 검증되기 전까지는 전자세금계산서 대신 **현금영수증**이 발행되고 **지급이 지연될 수 있다**고
애플이 명시한다.

**왜 SubFlow는 안 걸렸나**: 무료 앱이라 유료 앱 계약을 맺은 적이 없다. 계약이 없으면 세금 정보를
낼 일도, BRN을 물을 일도 없다.

**근거는 애플 정책이 아니라 한국 법이다.** 애플 도움말(한국 준수 정보):

> 한국에 기반을 둔 개인 또는 조직이라면 **전자상거래 소비자보호법**에 따라 Apple이 신원 정보를
> 수집·확인하여 앱 제품 페이지에 표시해야 한다. 유료 앱 계약에 서명했다면 한국 세금 양식에 입력한
> **BRN이 자동으로 표시**된다. 유료 콘텐츠를 제공하지 않고 계약에 서명하지 않았다면 BRN은 선택이다.

→ **유료 앱·앱 내 구입을 팔면 BRN 필수, 무료면 선택.**

⚠️ BRN은 **App Store 상품 페이지에 공개로 표시된다** (개인은 이메일 + BRN).

> **사업자등록을 낼지 말지, 간이·일반 중 무엇으로 할지는 세무 판단이다.**
> 소득신고·부가세 의무가 실제로 따라붙으므로 세무 상담을 받고 정할 것. 등록 자체는 홈택스에서
> 온라인 무료 신청이고 보통 2~3일 걸린다.

**→ 2026-09-28: B(무료 먼저)로 정했다. 아래 "출시 방식" 절 참고.**
따라서 **이 2번 절(유료 앱 계약)은 v1.0 에서 하지 않는다.** 유료화할 때 다시 읽을 것.

### 7. 프로덕션 빌드 → 제출

```
npx eas-cli build -p ios --profile production --non-interactive --no-wait
npx eas-cli submit -p ios --latest --non-interactive
```

- `--auto-submit`을 붙이면 빌드 후 업로드까지 간다 (빌드 ~5분 + 업로드 대기열 ~30분)
- ⚠️ `autoIncrement`는 **원격 카운터**라 "다음 빌드 = 승인된 빌드 + 1"이 아니다.
  만들기 전에 `npx eas-cli build:list`로 확인
- (유료화할 때) 앱 내 구입은 **심사 때 앱과 같이 심사된다** → 심사 메모에 상품 구조를 설명할 것

### 8. 심사

- 첫 제출에서 **Guideline 2.1(정보 요청) 반려는 흔하다.** SubFlow도 그랬다. 앱 결함이 아니라
  "정보를 더 달라"는 요청이었다
- ⚠️ 심사 메모와 회신 칸은 **각각 4,000자 제한**. 넘으면 잘리는 게 아니라 버튼이 비활성화된다
- 회신을 **먼저** 보내고 그다음에 빌드 교체 → 심사 업데이트 순서로
- v1.0 은 무료·로그인 없음·서버 없음이라 물어볼 거리가 적다. 유료화 뒤에는 **구매 복원 버튼**(설정에 있음 ✓)과
  코코몬 카드 등급이 무작위인 점(뽑기 = 확률 공개 의무가 있는지)을 물어볼 수 있다

### 9. 출시 후

- ⚠️ **JS만 바뀐 수정은 `eas update`(OTA)로 심사 없이** 나간다. 네이티브가 안 바뀌면
  runtimeVersion이 같아서 기존 빌드에 그대로 붙는다
- 새 빌드가 필요하면 `app.json`의 `version`을 **1.0.1**로 올린다 — 심사를 통과한 1.0.0에는
  새 빌드를 못 올린다
- 운동 건강 연동(HealthKit)은 출시 후 업데이트로 (카테고리가 이미 있어 새 상품 등록이 없다)

## 기간

| 구간 | 걸리는 시간 |
|---|---|
| 폰 검증 + 고치기 | 며칠 ~ 1주 (제일 큰 변수) |
| 스크린샷·문구·설문 | 1~2일 |

롤 이어붙이기는 **아직 실기기에서 한 번도 안 돌았다.**

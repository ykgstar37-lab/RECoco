# App Privacy 설문 답안 (레코코)

App Store Connect → 앱 개인정보 보호. SubFlow는 8개 유형을 신고했는데,
**레코코는 계정도 서버도 없어서 훨씬 단순하다** — 신고할 것은 버그 신고 한 곳뿐이다.

## 결론: 3개 유형만 "예"

모두 **버그 신고를 사용자가 직접 보낼 때만** 수집된다.
전부 `추적: 아니요` · `목적: 앱 기능` · `신원 연결: 아니요`.

| 유형 | 무엇 | 근거 (코드) |
|---|---|---|
| **연락처 정보 → 이메일 주소** | 신고에 답장받을 연락처를 적으면 | `support.ts` `report.contact` (선택 입력) |
| **사용자 콘텐츠 → 사진 또는 비디오** | 신고에 붙이는 스크린샷 (최대 3장) | `support.ts` `pickReportPhotos` |
| **사용자 콘텐츠 → 고객 지원** | 신고 종류와 적어주신 내용 | `support.ts` `report.type` / `report.detail` |

### 진단 데이터는?

신고에 앱 버전·기기 종류·OS 버전·기록 **개수**가 같이 간다
(`support.ts`: `version`, `device`, `recordCount`).

- 이것만 별도로 **"진단 → 기타 진단 데이터"**를 추가로 체크해도 되고,
  위 "고객 지원"에 포함된 것으로 보아도 된다. **SubFlow는 따로 체크했다** —
  같은 기준을 유지해 **체크하는 쪽을 권한다**.
- 기록 개수는 숫자 하나일 뿐 기록 내용이 아니다.

### "신원 연결"을 아니요로 두는 이유

계정이 없어서 사용자 식별자가 없다. 이메일은 **적어주신 분만** 적고, 그것을 키로
무엇을 모으지 않는다. 다만 보수적으로 가려면 이메일 항목만 `신원 연결: 예`로 둬도
심사에 불리하지 않다.

## "아니요"로 두는 것과 그 근거

| 묻는 것 | 답 | 근거 |
|---|---|---|
| 추적(Tracking) | **아니요** | 분석·광고 SDK가 하나도 없다 (`analytics|firebase|sentry` 검색 결과 0) |
| 위치 | 아니요 | 위치 권한을 요청하지 않는다. 장소 검색은 사용자가 친 글자로만 |
| 구입 내역 | 아니요 | 결제는 App Store가 처리하고, 앱은 무엇을 샀는지만 기기에 저장한다 |
| 식별자 | 아니요 | 사용자 ID·기기 ID를 만들거나 보내지 않는다 |
| 사용 데이터 | 아니요 | 화면 조회·상호작용을 기록하지 않는다 |
| 연락처·건강·금융 정보 | 아니요 | 받지 않는다 (건강 연동은 출시 후 업데이트 때 다시 답할 것) |

### 검색어(카카오·TMDB)를 신고하지 않는 이유

검색어는 검색 결과를 받는 **그 요청에만** 쓰이고, 저장하지도 신원과 잇지도 않으며
추적·광고·프로파일링에 쓰이지 않는다 — 애플의 선택적 공개 예외에 해당한다.
개인정보 처리방침에는 **명시했다**(2절 표). SubFlow도 같은 판단으로 IP를 신고하지 않았다.

⚠️ 나중에 검색어를 저장하거나(최근 검색어 목록 등) 서버를 두게 되면 이 답을 다시 볼 것.

## 개인정보 처리방침 1:1 대조

심사자가 설문과 방침이 어긋나는지 본다. 어긋나면 반려된다.

| 설문 답 | 방침 어느 줄 |
|---|---|
| 이메일 주소 (고객 지원) | 2절 표 "버그를 신고할 때 → 남기신 연락처" |
| 사진 또는 비디오 (고객 지원) | 2절 표 "고르신 스크린샷" |
| 고객 지원 | 2절 표 "적으신 내용" |
| 기타 진단 데이터 | 2절 표 "앱 버전, 기기 종류와 OS 버전, 기록 개수" |
| 추적 아니요 | 3절 "광고를 넣지 않습니다 / 추적하거나 분석 도구를 넣지 않습니다" |
| 위치 아니요 | 3절 "위치를 받지 않습니다" |
| (신고 안 함) 검색어 | 2절 표 "입력하신 검색어만 → 카카오·TMDB" |

방침 원본: `landing/privacy.html` → `https://recoco.pages.dev/privacy`
